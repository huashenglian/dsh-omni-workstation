# v2.9.3 — MiniMax 音色克隆（AI 工具 + 面板）

> [Back to AGENTS.md](../../../AGENTS.md) · [Changelog ↗](../changelog/changelog.md)

## 何时读取
排查 voice 工具不注册、`/omni/minimax/clone` 报错、mimo↔minimax 切换不生效、agent 调 `speak` 走错分支、或做 provider-gated 注册设计前先读本节。

## 背景 / 目标
v2.9 语音模块仅跑通 MiMo 供应商，MiMo 的零注册音色克隆（base64 采样入 `audio.voice`）在 MiMo 上可用但受限于单一供应商。用户要求接入 MiniMax 语音 API 做音色克隆+合成，走**服务端两步克隆流程**（先上传参考音频获取 `file_id`，再以 `file_id` 创建 voice_id），并给面板一个可点击的克隆入口。

## 设计要点

- **provider-gated 注册**：`voiceSig` 加入 `provider`，minimax↔mimo 切换触发 `syncToolRegistration` 重注册；minimax 下**不注册** mimo `clone_voice`（它硬编码 `mimo-v2.5-tts-voiceclone`→`runMimoTts`，在 minimax endpoint 上必坏），改注册 `minimax_clone_voice`；三 disposer（`voiceDisposer`/`cloneDisposer`/`minimaxCloneDisposer`）独立清理
- **合成路由**：`speak` 工具 execute 按 `voiceConfig.provider` 分派——`mimo`→`runMimoTts`，`minimax`→`runMinimaxTts`；`outputFormat` 在 minimax 下被忽略（`t2a_v2` 仅支持 mp3）
- **key 写入路径**：minimax key 走 `POST /omni/config {voiceConfig:{field:'apiKey',value:'…'}}`（applyPatch 写回 `voiceConfig.apiKey`）；**勿用 `/omni/key {voice:true}`**——该路由只读且无 voice 分支（仅 `video/imggen/cardId`）
- **MiMo 源码未改**：`runMimoTts`/`buildCloneVoiceToolDef` 保持原样，只在注册门控上做 provider 判断
- **非 mimo/minimax 合成**：doubao/indextts/voxcpm/gptsovits 等仍留待后续（`VOICE_PROVIDERS` 端点不变）
- **key 不落仓库**：运行时写入 `omni-vision.json`（git 忽略）

## 协议实现（index.js）

### `minimaxBase(region)`
region 字段驱动 base URL：
- `cn` → `https://api.minimaxi.com`
- `global` → `https://api.minimax.io`

### `runMinimaxTts(vc, args, exec)`
`POST {base}/v1/t2a_v2`，`Authorization: Bearer {vc.apiKey}`，body：
```json
{
  "model": vc.model,
  "text": args.text,
  "stream": false,
  "output_format": "hex",
  "language_boost": "auto",
  "voice_setting": { "voice_id": vc.voiceId || args.voice },
  "audio_setting": {
    "sample_rate": 32000,
    "bitrate": 128000,
    "format": "mp3",
    "channel": 1
  }
}
```
解析 `data.audio`（hex 字符串）→ `Buffer.from(audioHex, 'hex')` → mp3 buffer。输出目录：`sessionCwd(exec)` → `<cwd>/.omni-workstation/artifacts/voice_<ts>.mp3`。**回退链为空则抛错，不回退 `process.cwd()`**（镜像 `generate_video` 模式）。返回 `{ok, path, model, format:'mp3'}`。

### `doMinimaxClone(vc, refPath, voiceId, text, model)`
复用工具，面板路由 + `minimax_clone_voice` AI 工具共同调用。两步：

1. **上传**（multipart）：`POST {base}/v1/files/upload`，`Authorization: Bearer {vc.apiKey}`，`FormData`：
   - `purpose=voice_clone`
   - `file=FileObject`（`new Blob([buf])` + filename，Node 18+ 全局可用）
   - **关键**：`httpJson` 只 `JSON.stringify(body)`，**不支持 multipart**——必须用原生 `fetch` + `FormData`
   - 返回 `data.file_id`

2. **克隆**（JSON）：`POST {base}/v1/voice_clone`，`Authorization: Bearer {vc.apiKey}`，body：
```json
{
  "file_id": "<from step 1>",
  "voice_id": "<user-provided>",
  "text": text || "",
  "model": vc.model,
  "need_noise_reduction": false,
  "need_volume_normalization": true,
  "aigc_watermark": false
}
```
返回 `data.voice_id` + 可选 `data.demo_audio`。

### `POST /omni/minimax/clone`（面板路由）
面板 `MinimaxCloneSection` 调用。请求体二选一：
- `ref_audio_path`（服务器端绝对路径）：直传 `doMinimaxClone`——给 AI 工具/e2e 用
- `base64 + mime`：面板文件输入转 base64，服务端落 `<configDir>/voice-library/` 临时文件后调 `doMinimaxClone`

前置校验：`voiceConfig.provider==='minimax'` + `isVoiceConfigValid`，否则 400。返回 `{ok, voice_id, file_id, demo_audio}`。

### `minimax_clone_voice` AI 工具（`buildMinimaxCloneVoiceToolDef(vc)`）
一次调用完成「上传采样→克隆→合成」：

| 参数 | 必填 | 说明 |
|---|---|---|
| `text` | 是 | 要合成的文本 |
| `voice_sample_path` | 是 | 参考音频文件路径（本地绝对路径） |
| `voice_id` | 否 | 音色 id，缺省自动生成 `hutao_<ts>` |
| `style` | 否 | 自然语言风格指令 |

流程：`doMinimaxClone(vc, samplePath, voiceId, text, vc.model)` → 拿到 `voice_id` → 用该 `voice_id` 调 `runMinimaxTts` 合成文本 → 返回 mp3 路径。**一次性**（不复用 voice_id；后续复用靠面板克隆得到 voice_id 后 patchVoice 持久化）。

## UI 变更（client.js）

### `MinimaxCloneSection` 组件
- 仅 `provider==='minimax'` 时渲染，插入语音面板 TTS 子 tab 的 minimax 段
- 三段：**隐藏文件输入**（`<input type="file" accept="audio/*">`）→ base64 转码；**voice_id 输入框**（placeholder 来自 i18n `voiceCloneVoiceIdPh`）；**克隆按钮**（`voiceCloneBtn`）

### i18n keys（en/zh）
`voiceCloneSection` / `voiceCloneVoiceIdPh` / `voiceCloneBtn` / `voiceClonePickRef` / `voiceCloneOk` / `voiceCloneFail`

## 失败尝试
- 误用 `/omni/key {voice:true}` 写 minimax key：该路由无 voice 分支且只读 → key 永不写入 → `isVoiceConfigValid` 失败 → voice 工具不注册 → e2e 全死。正确写法见上述 key 写入路径
- 试图用 `httpJson` 发 multipart：`httpJson` 内部 `JSON.stringify(body)` 会把 `FormData` 变成 `{}` → 上传失败。改用原生 `fetch` + `FormData` + `new Blob([buf])`
- 在 minimax 下继续注册 mimo `clone_voice`：`buildCloneVoiceToolDef` 硬编码 `mimo-v2.5-tts-voiceclone`→`runMimoTts`，`runMimoTts` 又硬编码 MiMo endpoint，minimax key 打 MiMo 域名必然失败。改为 provider-gated 注册 + `minimax_clone_voice` 独立工具
- 沿用 `runMimoTts` 的 `process.cwd()` fallback：会落错工作区（AGENTS 已记的 cwd gotcha）；`runMinimaxTts` 采用与 `generate_video` 一致的严格模式——`sessionCwd` 空则抛错
