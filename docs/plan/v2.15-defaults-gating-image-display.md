# v2.15 默认值 / 工具门禁 / 图片展示 / dsh 启动修复 实施计划

> **状态：待评审，尚未执行。** 本文件只做调查记录与实施方案，没有改动任何插件代码。
>
> 执行方式（评审通过后二选一）：逐任务执行并每任务提交，或整体执行后统一 E2E。

**目标：** 让插件在“默认全开”的同时只在配置真正可用时把工具与提示词交给 AI；auto-vision 自动路由默认关闭；在不重复造轮子的前提下强化 `show_image`；修复本地 dsh 源码树 `dsh web` 因缺少构建产物而启动失败。

**架构：** 宿主半（`lib/index.js`）集中出 6 个“模块是否可用”纯函数，所有工具注册、`/omni/config` 可见性、日志摘要、提示词分支统一引用它们；客户端半只消费 `/omni/config` 的结果。图片展示不删除 `show_image`，而是补齐原生 `read_image` 已具备的“点击放大”交互，并让输出路径可被 dsh 原生 Markdown 图片渲染器识别。dsh 启动问题只通过构建源码树解决，不修改 dsh 源码。

**技术栈：** Node 24 / cordis / dsh 0.2.2-alpha.2 / React（client.js 内联）/ Playwright + pytest（E2E）

## 0. 结论摘要

| # | 需求 | 结论 |
|---|---|---|
| 1 | VLM 模块的 “auto-vision 自动路由” 默认关闭 | 当前 3 处默认 `true`（`defaultMirrorConfig`、`normalizeMirrorConfig`、`maskedMirror`）+ 客户端 3 处默认值。全部改为默认 `false`；已显式写 `true` 的旧配置保持 `true`（不强制迁移）。 |
| 2 | 默认打开所有模块；配置不完整不提供工具/提示词 | 模块开关默认改为开（VLM / 生图 / 视频 / 语音 / 工具箱）。工具注册统一走新的 `xxxLive()` 谓词：**必须有一份完整配置**（endpoint/model/key 或等价字段）才注册。**兜底模型不再单独点亮 `analyze_image`**。`ocr_image` / `detect_elements` 需要至少一张有效 VLM 卡片。同步修正 `resolveVerifyReminderMode`、`viewImageToolHint`、`analyze_image` 描述中的死引用。 |
| 3 | dsh 是否自带图片展示；移除还是强化 `show_image` | dsh **自带 3 套**图片展示：① `read_image` 工具行内画廊 + 灯箱；② 助手 Markdown 绝对路径图片 + 灯箱；③ 工作区侧栏图片预览（缩放/平移，png/jpg/gif/webp/bmp/ico/svg）。但 `read_image` 在纯文本模型路由上**直接拒绝**、每次只能读 1 张、且会把图片送进模型（耗图 token）；工具结果文本不经过 Markdown 渲染。`show_image` 仍不可替代（纯文本模型展示、一次 8 张、可展示生成图）。**结论：保留 `show_image` 与工具箱开关，强化它**：点击放大灯箱 + 输出绝对路径（可被 dsh 原生 Markdown 图片渲染器接住）。 |
| 4 | `dsh web` 启动失败 | 根因是**本地 dsh 源码树没有构建产物**，不是插件问题：6 个 client 包缺 `lib/client.js`，`ui-trajectory` 缺 `lib/typert.host.js`。`dsh` 命令是 `C:\Users\10741\bin\dsh.bat` → 源码树软链，所以每次都跑 `tsx apps/cli/src/bin.ts`。执行 `pnpm run build`（或 `build:artifacts`）即可。日志里的 3 个 plugin 版本不兼容是**非致命跳过**。 |

### 需要用户确认的 3 个决策（本计划已按推荐值编写）

- **D1（STT 子开关默认值）**：推荐 `sttEnabled` 保持**默认关**。理由：默认 STT 配置是 keyless 的本地 FunASR（`http://127.0.0.1:8000/v1` + `sensevoice`），按现有 `isSttConfigValid` 会判定“有效”；默认开启会在 AI 每次拿到音频时自动注册 `transcribe` 并打到大概率没启动的本地服务——正是需求 2 要消灭的“无效调用”。`ttsEnabled` 保持默认开（语音配置默认无效，工具仍不注册）。若你坚持“所有模块”包含 STT，可改为默认开 + 把 `defaultSttConfig()` 的 endpoint/model 置空，等用户在面板里显式选 FunASR 才填上。
- **D2（兜底模型是否算“已配置”）**：推荐**不算**。当前全新配置默认带 5 个 OVHCloud 兜底模型，`fallbackHasModels()` 为真 ⇒ 即使一张卡片都没有，`analyze_image` 也会注册（用户日志正是 `fallback=on`）。兜底只在“已有至少一张有效卡片、但全部失败”时作为救援通道使用。
- **D3（旧配置迁移）**：推荐**只改默认值，不改写用户已写入的显式 `false`**。用户当前 `~/.dsh/omni-vision.json` 里各模块都是显式 `false`，改完后仍需在设置页手动打开（或删除/改名配置文件让默认值重新生成）。不做一次性强制迁移，避免覆盖“用户故意关闭”的意图。

**对比结论：**

- 官方“展示效果”确实更强（灯箱、右键、拖拽、缩放/平移）。
- 但官方**能力不全**：纯文本模型路由看不了图；一次只能一张；工具结果不能走 Markdown；没有视频。
- 插件的 `show_image` 恰好覆盖这些空白：纯文本模型可用、一次最多 8 张、0 图 token、可展示 `generate_image` 产物。
- 因此**不删除** `show_image`，也不删除工具箱开关；只补齐它最弱的“点击放大”，并让输出路径可被原生 Markdown 接住。见任务 4。

## 2. 设计

### 2.1 统一门禁谓词（唯一真源）

在 `lib/index.js` 的 `validCards` 附近新增并导出（放 `validCards` 之后、`effectiveCard` 之前）：

```js
/** 至少一张用户配置的完整 VLM 卡片（兜底不算）。 */
const hasVlmCards = (cfg) => validCards(cfg).length > 0

/** VLM 模块真正可用：开关开 + 至少一张完整卡片。 */
const isVlmLive = (cfg) => !!cfg && cfg.vlmEnabled !== false && hasVlmCards(cfg)

/** 生图可用：开关开 + endpoint/model/key 完整。 */
const isImggenLive = (cfg) => !!cfg && cfg.imggenEnabled !== false && isImggenConfigValid(cfg.imggenConfig)

/** 视频可用卡片（enabled + config 完整）。 */
const videoLiveCards = (cfg) => (Array.isArray(cfg && cfg.videoCards) ? cfg.videoCards : [])
  .filter((c) => c && c.enabled !== false && isVideoConfigValid(c.config))
const isVideoLive = (cfg) => !!cfg && cfg.videoEnabled !== false && videoLiveCards(cfg).length > 0

/** 语音合成可用：总开关 + TTS 子开关 + 配置完整。 */
const isVoiceLive = (cfg) => !!cfg && cfg.voiceEnabled !== false && cfg.ttsEnabled !== false && isVoiceConfigValid(cfg.voiceConfig)

/** STT 可用：总开关 + STT 子开关 + 配置完整（D1 决定默认子开关）。 */
const isSttLive = (cfg) => !!cfg && cfg.voiceEnabled !== false && cfg.sttEnabled !== false && isSttConfigValid(cfg.voiceConfigStt)

/** 媒体分析可用：卡片开了 video/audio 且协议真的支持。 */
const isMediaLive = (cfg) => {
  const cards = validCards(cfg)
  const video = cards.some((c) => c.video === true && protocolMediaSupported(effectiveCard(c)))
  const audio = cards.some((c) => c.audio === true && protocolMediaSupported(effectiveCard(c)))
  return video || (audio && !isSttLive(cfg))
}

/** 工具箱实际会注册的工具名（ocr/detect 依赖 VLM 卡片）。 */
const VLM_TOOLKIT_TOOLS = new Set(['ocr_image', 'detect_elements'])
const toolkitToolNames = (cfg) => {
  if (!cfg || cfg.visionToolsEnabled === false) return []
  return VISION_TOOL_NAMES.filter((n) =>
    (cfg.visionToolToggles || {})[n] !== false &&
    (!VLM_TOOLKIT_TOOLS.has(n) || hasVlmCards(cfg)))
}
```

注意：`isVlmLive` **不**包含 `fallbackHasModels`（D2）。兜底仍由 `askVlm` 在卡片全部失败后使用，只是不再决定工具是否注册。

所有列在 §1.2 的重复谓词改为引用这些函数。`configSummary` 输出改为：

```text
vlm=off toolkit=on(5/7) media=off imggen=off video=off tts=off stt=off fallback=on
```

这样 E2E 看一行日志就能确认“工具箱只注册了不依赖 VLM 的 5 个”。

### 2.3 图片展示决策

保留 `show_image` / `show_video` 与工具箱开关，做 3 处强化：

1. **点击放大**：`ToolImageCard` 内新增灯箱状态；点击缩略图 → 同页遮罩 + 原图（`max-width:90vw; max-height:86vh; object-fit:contain`），Esc / 点遮罩 / 关闭按钮退出。复用现有 `.omni-confirm-overlay` / `.omni-video-modal` / `.omni-video-close` 样式，新增 `.omni-img-btn` / `.omni-img-modal-el` 两条 CSS。
2. **输出绝对路径**：`show_image` 的 render 文本由 `![](file:///D:/...)` 改为 `![](D:/...)`；`generate_image` 的 render 同样改。这样 AI 在正文里复述路径时，dsh 的 `AssistantMarkdown` 会通过 `/api/file?path=` 原生渲染 + 灯箱（`file:///` 会被拒绝）。
3. **保留多图与高度设置**：`image_paths` ≤ 8、`showImageMaxHeight` 不变；视频播放器不变（dsh 无原生视频展示）。

## 6. 风险与回滚

| 风险 | 影响 | 缓解 |
|---|---|---|
| auto-vision 默认关 | 依赖 `auto-vision` 路由的旧用户升级后模型选择器少一项 | 显式 `true` 不迁移；文档写明开关位置；回滚只需恢复 3 处默认值 |
| 模块默认开 | 用户以为“开了就该有工具”，但配置无效时工具仍隐藏 | 面板状态行继续显示“工具已隐藏（无有效配置）”；文档补一句“开关只决定上限” |
| 兜底不再点亮 VLM | 只靠兜底模型、不配卡片的用户升级后 `analyze_image` 消失 | 这是需求 2 的预期；在 changelog 写明；如需要可加“兜底作为主通道”开关（本计划不做） |
| 默认 STT 关（D1） | 与“所有模块默认开”的字面理解不一致 | 计划中明确 D1；若改全开，需同时把默认 STT endpoint/model 置空 |
| 构建耗时/失败 | `pnpm run build` 可能 10-30 分钟，Windows 原生插件可能失败 | 先 `build:artifacts`；最小回退 `generate-typert + build:lib:client`；失败时保留日志再诊断 |
| 旧配置显式 false 不迁移 | 用户当前配置改完仍全关 | 设置页手动打开（或改名配置文件重新生成）；不做强制迁移（D3） |

**回滚点：** 每个任务一个原子提交，按提交逆序 `git revert` 即可；dsh 构建产物可直接删除 `lib/` 后重新构建，不影响源码。
