# v2.14 — 适配 dsh CLI/headless：配置文件双位置 + 免重启热加载 + JSON Schema

> 目标：让插件在没有 web 服务的 dsh 组合（`dsh --profile headless "…"`）里也能用，并且**只靠编辑配置文件**完成配置（不新增任何斜杠指令 / CLI 子命令）。
> 状态：已实施（package.json 版本号仍为 `0.1.2`，按约定发布时才提）。

## 1. 问题（探查结论）

| 事实 | 位置 / 依据 |
|---|---|
| `inject = ['tools', 'webServer', 'llm']`，cordis 语义为「inject 内服务全部可用才加载」 | `lib/index.js:37`、`docs/cordis-api/registry.md` |
| `@deepseek-ai/dsh-headless` 的 patch 明确「mounts no Host, HTTP server, Web runtime」 | `packages/bundle/headless/cordis.patch.yml` |
| ⇒ **CLI/headless 面插件根本不加载**，全部工具缺失（真 bug，不只是"没有设置页"） | 上两条推导 |
| 配置固定在插件安装目录（`import.meta.url` 推导），`dsh plugin update/remove` 会连同 `.bak` 一起删；web / headless 两个 profile 各自一份 | `lib/index.js:1528-1543` |
| `webServer.register()` 重复路径直接 throw；harness 内的正确写法是 `ctx.effect(() => ctx.webServer.register(...))` | `packages/host/webserver/src/index.ts:366-373`、`packages/host/open-in-app/src/index.ts:193` |
| 每次 `loadConfig()` 都读盘（28 处调用）⇒ 配置**值**本来就实时，缺的只是工具/路由/twin 的注册对账 | `lib/index.js` |
| 解析失败时旧实现 `copyFileSync(bak, file)` 会覆盖用户文件（手改一个逗号就丢整份改动） | `lib/index.js:1592-1605`（旧） |
| `normalizeConfig()` 只回填已知字段 ⇒ `$schema` 必须在写盘时补 | `lib/index.js:1441` |
| README「卸载后配置原样保留」与事实不符（插件目录内配置会随插件删除） | README 旧版「Uninstall」段 |

## 2. 决策

1. **双位置兼容**：home 文件优先（`~/.dsh/omni-vision.json`，跟随 `$DSH_HOME`），插件目录旧配置继续可用；两处都没有时**新装写 home**（否则新用户又落到 `node_modules`）。不自动搬家、不删用户文件。
2. **全量 DX**：JSON Schema 补全 + 改文件免重启 + 启动日志打印路径与生效状况。
3. **不新增指令**：配置只走文件；斜杠指令数量不变。
4. 版本号不动（`0.1.2`），按开发里程碑 `v2.14` 记 changelog。

## 3. 实现

### 3.1 新增 `lib/config-path.js`（纯函数，无第三方依赖）

`resolveDshHome(env)`（`$DSH_HOME` 非空白 → 展开 `~` → `resolve`，否则 `~/.dsh`）、
`expandHomePath`、`backupPathFor`、`configDirOf`、
`resolveActiveConfig({ pluginDir, env, exists })` → `{ file, backupFile, pluginFile, homeFile, source, dshHome }`，
`source ∈ env | home | plugin | home-new`。

### 3.2 `lib/index.js`

- `inject = ['tools', 'llm']`；`homedir` import 移除，`copyFileSync` 移除。
- 配置层：`configPathInfo()`（每次读取重解析，失败回退插件目录）+ `activeConfigPaths()`（路径变化日志）+ `configFile()` / `backupFile()`；删除 `legacyConfigDir/legacyConfigFile`。
- `loadConfig`：缺失 → 默认配置立刻落盘；解析失败 → **只内存回退 `.bak`**，文件不动，warn 带路径 + 原因。
- `storeConfig`：`mkdirSync(recursive)` → `ensureSchemaBeside()` → `Object.assign({ $schema }, normalizeConfig(cfg))` → `writeJsonAtomic`（temp + rename）→ `.bak` → 记 `selfWriteStamp`。
- 启动报告 `reportBootConfig(ctx)`：`config: <path> (<source>) | vlm=… toolkit=… media=… imggen=… video=… tts=… stt=… fallback=…`，加 headless 提示、旧位置/双份/全关 warn。
- 热加载 `maybeResyncFromDisk(why)`：`configStamp()`（path+mtimeMs+size）比对 → `syncToolRegistration()` + `syncBuilderCommand()`；挂在已有的 `agent/pre-step`（每步至多一次，`configResyncInFlight` 防重入），外部编辑才 info，自己写盘只 debug。
- 路由：`apply()` 末尾 `bindWebRoutes(ctx)` + `ctx.inject(['webServer'], …)` 兜底；`bindWebRoutes` 用 `WeakSet<ctx>` 守卫 + `ctx.effect` 收集 14 个 disposer（reload 安全）；`webServer.register({` → `bind({`（14 处）。
- `GET/POST /omni/config` 的 `path` 跟随新解析。

## 4. 失败模式与边界

| 情况 | 行为 |
|---|---|
| `$DSH_HOME` 空白/未设 | 用 `~/.dsh`；`~` 前缀先展开；相对路径 `resolve()` |
| home 不可写 | warn，回退插件目录（不崩） |
| 两份配置同时存在 | home 优先 + warn 一次（不删不搬） |
| JSON 语法错误 | 不覆写；内存回退 `.bak`；改好存盘即恢复（热加载自动重试） |
| 一个模块都没生效 | 启动 warn 指出文件与缺项（`endpoint/model/apiKey`） |
| 多 profile 并发写 | temp+rename 原子替换；不做语义合并（已知限制） |
| webServer 晚于插件提供 | `ctx.inject(['webServer'], …)` 补绑；`WeakSet` 守卫防重复 register |
