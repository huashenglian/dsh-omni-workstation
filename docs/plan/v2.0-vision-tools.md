# v2.0 — 视觉工具箱（Vision Toolkit）(2026-08)

> [Back to root AGENTS.md](..) · [v1.9 ↗](./v1.9-mirror-card.md) · [Changelog ↗](../changelog/changelog.md)

## 目标

在 `analyze_image` 之外,为 AI 提供 6 个可调用视觉工具,覆盖「放大细看 / 取色 / 像素对比 / 文字识别 / 元素定位 / 图片展示」六类高频视觉诉求:

- 本地 4 工具(`zoom_image` / `sample_colors` / `image_diff` / 本地 OCR)零 token 成本;
- OCR 本地优先、VLM 兜底;元素检测与图片展示走既有 VLM 卡片 failover 链;
- 全链路 token 最小化:工具只返回紧凑 JSON + 工件路径,不把图片字节回传给模型;
- 与参考插件 dsh-vision-router 在工具命名上完全区隔,避免 harness 唯一性冲突。

## 6 工具规格

统一入参约定:`image_path`(本地路径)与 `attachment_id`(形如 `sha256:` 附件 id)二选一,由共享 `resolveImage(exec, args)` 解析为 `{buffer, mime}`;可选参数**整个省略 `required` 键**(`required:false` 破坏 schema 校验)。失败一律 `throw new Error('<工具名>: 中文错误信息')`,需模型可见的结构化失败返回 `{ ok:false, code, ... }`。

### zoom_image — 局部放大(纯本地)
- `region`(必填) `"x1,y1,x2,y2"`,四项全在 [0,1] 按宽高分数、否则按原图像素;越界 clamp,退化区域抛错。
- 裁剪落盘 `<cwd>/.omni-workstation/artifacts/zoom_<ts>.png`,返回 `{path,width,height,source_width,source_height}`。
- 描述引导:裁剪后可再调 `analyze_image` 细看该区域。

### sample_colors — 主色调采样(纯本地)
- 可选 `region` 限定区域;区域裁剪后 64×64 缩放 + 32-bin 量化(`top` 默认 8,≤64)。
- 返回 `{colors:[{hex,count,share}],source_width,source_height}`,按占比降序;alpha<128 像素跳过。

### image_diff — 像素对比(纯本地)
- `original`/`compare` 各接受本地路径或 `"sha256:<附件 id>"`;尺寸不一致时 compare 最近邻缩放到 original 尺寸。
- 8×8 网格平均 RGB 距离 > `threshold`(默认 16,0~442)记为差异格:返回 `{diffRatio,diffCells,worstRegions(≤5),heatmapPath,width,height}`。
- 热力图与原图同尺寸(差异格红色热斑,其余保持原色),落盘 `diff_<ts>.png`。

### ocr_image — 文字识别(本地优先自动降级)
- `engine`: `auto`(默认,本地优先)、`local`(仅本地)、`vlm`(仅视觉模型)。
- 本地:Tesseract `chi_sim+eng`、`--psm 6`、20s 超时、32MB maxBuffer;二进制探测进程内缓存。
- 降级:auto 且本地失败/为空 → `askVlm` 固定转写 prompt,8000 字符软上限(超长截断)。
- 返回 `{engine:'local'|'vlm', text, model, api}`;`local` 不可用 → `{ok:false, code:'LOCAL_OCR_UNAVAILABLE'}`;无可用卡片 → `code:'NO_VLM_CARDS'`。

### detect_elements — 元素检测(VLM)
- VLM 严格 JSON 数组 `[{number,label(≤40字),box{x1,y1,x2,y2}}]`,box 为**原图像素**整数坐标,最多 20 项。
- >4MP 先最近邻降采样再问 VLM(坐标仍按原始尺寸换算);JSON 解析失败(no-array-in-answer / Unexpected / Expected)用更强 prompt 重试一次,仍失败返回 `VLM_BAD_JSON` + 原始文本前 500 字符。
- 逐项 box clamp、丢弃退化项;`annotate`(默认 true)在原始分辨率上用 2px 循环调色板边框画标注图落盘 `annot_<ts>.png`。

### show_image — 图片展示
- markdown `![label](file:///<path>)` 内联;`attachments` 服务存在时经 `saveImage` 注册附件并追加 `{type:'image', attachment}` 块;客户端 `tool.call.toolview` 卡片渲染预览。
- 附件源先物化到 artifacts(`show_<ts>.<ext>`);attachment 为 null 时省略该键(避免 nullable-object 破坏 must-be-object 校验,与 generate_image 同处理)。

## token 优化设计

1. **紧凑结果**:所有工具只返回 JSON + 工件路径,图片字节绝不回传给模型;模型按需再调 `analyze_image` 传入路径/附件 id 细看。
2. **tool-result 图片改写(agent/pre-step 两层 sanitize)**:`agent/request` 只返回 provider/model 配置、`messages` 在其后才注入、且 compaction 直接 `session.deriveMessages()` 绕过它——所以第一版放 agent/request 的剥离器在 E2E 中被证明失效(show_image 后 compaction 报 `UNSUPPORTED_CONTENT`)。修复 = 在 `agent/pre-step` 处理器:① 用 `session.append('tool/result', …, { surfaceOp:{op:'replace'} })` 把会话表面上含 image 块的 `tool/result` 事件影子替换为文本标记(`toolImageMarker`,含附件 id 与「可调 analyze_image 细看」提示),拦到 `deriveMessages()` 与 compaction;② 把当步 claimed 消息里的工具图片块改写为标记。用户消息图片不受影响(由 harness 准入门控)。waterfall **必须 await next() 且 return decision/config**,否则毁掉 agent。
3. **工具协同靠描述引导**:各工具 description 明确写出「得到 box/路径后 → 再调 analyze_image / zoom_image」的接续方式,不注入每轮提醒。

## 与 dsh-vision-router 的对照与取舍

| 维度 | dsh-vision-router(参考) | dsh-omni-workstation v2.0 |
|---|---|---|
| 工具命名 | `vision_crop`/`vision_colors`/`vision_present` 等 | `zoom_image`/`sample_colors`/`image_diff`/`ocr_image`/`detect_elements`/`show_image`(完全区隔) |
| 图片来源 | 各自独立实现 | 共享 `resolveImage`(路径/附件双通道) |
| VLM 请求 | 独立 | 复用 `askVlm` = analyze_image 同一 failover 链(超时/JPG→PNG/降采样兜底) |
| 本地零 token | 部分 | 4 工具纯本地,OCR 本地优先降级 |
| 产物 | 图片字节入上下文 | 只回紧凑 JSON + 工件路径 |

取舍:不复刻 dsh-vision-router 的命名与实现;工件落盘 `<cwd>/.omni-workstation/artifacts/` 换取 token 最小化,代价是模型看不到图片字节,需经 `analyze_image` 二次读取。

- `lib/vendor/png.js` 新增 `decodePng`:8-bit 非隔行 color type 0/2/3/4/6;不支持类型抛 `PNG_UNSUPPORTED` 错误码。`decodeAny()` 据此统一 JPEG/PNG → RGBA 像素管线(jpeg-js 只解码 JPEG)。

- `package.json` `files` 增加 `lib/vision-tools.js`。
